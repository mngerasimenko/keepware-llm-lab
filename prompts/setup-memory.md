# Промпт: разверни файловую память в этом проекте

Дайте это своему агенту (Claude Code или совместимому) в корне проекта, где нужно поднять память. Агент выполнит развёртывание сам. Промпт самодостаточный - репозиторий рядом держать не обязательно.

Шаги здесь совпадают с ручной инструкцией из [`../CLAUDE.example.md`](../CLAUDE.example.md) и [README](../README.md) - если правите один, правьте и другой.

---

Твоя задача - развернуть в этом проекте долговременную файловую память на markdown-файлах (без вектор-БД), чтобы она лежала в проекте под git, а не в системной папке. Действуй по шагам и в конце отчитайся. Ничего не коммить - оставь изменения владельцу. Если что-то неоднозначно - спроси.

**1. Отключи встроенную авто-память Claude Code.** В `.claude/settings.json` проекта выставь `"autoMemoryEnabled": false` (создай файл или аккуратно смёржь, не затерев существующие ключи):
```json
{
  "autoMemoryEnabled": false
}
```
Иначе просьбы «запомни X» уходят в системную папку `~/.claude/projects/<проект>/memory/` мимо проектного `./memory/`.

**2. Найди конфиг-файл агента.** Claude Code читает и `./CLAUDE.md`, и `./.claude/CLAUDE.md`. Определи, какой уже есть; если нет ни одного - создай `./CLAUDE.md`. Запомни его путь - он важен для шага 6.

**3. Создай папку `memory/`** в корне проекта, если её ещё нет.

**4. Предложи перенос из нативной памяти (спроси владельца, не переноси молча).** Найди папку нативной авто-памяти этого проекта: она в `~/.claude/projects/<путь-проекта-с-заменёнными-разделителями>/memory/` (например для `C:\javaProjects\bankrest` это `~/.claude/projects/C--javaProjects-bankrest/memory/`). Если папки нет или она пуста - пропусти шаг. Если в ней есть записи - **спроси владельца и дождись ответа**, например: «Нашёл в нативной памяти N записей: <кратко перечисли>. Перенести их в проектный `./memory/`? Все, выборочно (укажи какие) или не переносить?». По ответу:
- перенеси выбранные факты в `./memory/` в нашем формате (frontmatter `name` / `description` / `metadata.type` + тело);
- затем **заархивируй** нативную папку переименованием `memory` → `memory.bak` (не удаляй - так перенос обратим);
- если владелец сказал не переносить - оставь нативную папку как есть, ничего не трогай.

**5. Заведи 2-4 стартовых факта из проекта** (реальных, из файлов - README, `package.json`/`pom.xml`/`pyproject.toml`, конфиги, существующий `CLAUDE.md`, папки с доками; не дублируй уже перенесённое из шага 4). Не выдумывай. Кандидаты:
- `project_<имя>.md` (`type: project`, `<имя>` - слаг латиницей) - что за проект, стек, как запускать/тестировать;
- `feedback_<имя>_conventions.md` (`type: feedback`) - конвенции, если нашёл (стиль коммитов, язык, правила из текущего конфига) - с «почему»;
- `reference_<имя>_docs.md` (`type: reference`) - где документация/дашборды/тикеты, если есть.

Формат каждого файла:
```markdown
---
name: <имя этого файла без .md - в точности, буква в букву>
description: <одна строка про то, ЧЕМ является файл - стабильный крючок, не журнал фактов>
metadata:
  type: user | feedback | project | reference
---

<сам факт. Связи - через [[имя-другого-файла]].>
```

**6. Создай индекс `memory/MEMORY.md`** - по одной строке на каждый файл памяти (стартовые + перенесённые):
```markdown
- [Заголовок](file.md) - короткий крючок
```

**7. Подключи индекс импортом и вставь протокол в конфиг из шага 2.** Путь импорта считается относительно файла, где стоит строка:
- если конфиг - корневой `./CLAUDE.md` → строка `@memory/MEMORY.md`;
- если конфиг - `./.claude/CLAUDE.md` → строка `@../memory/MEMORY.md`.

Допиши в тот же файл раздел «## Память» (текст ниже - канонический, совпадает с `CLAUDE.example.md`):
```markdown
## Память

Долговременная память - файлы в `./memory/`: индекс `MEMORY.md` (подключён импортом выше, уже в контексте - отдельно читать не нужно) плюс по одному факту на файл с YAML-frontmatter `name` / `description` / `metadata.type` (`user` | `feedback` | `project` | `reference`). Связи между фактами - через `[[имя-другого-файла]]`.

Правила:

- **Что записывать (не всё подряд):** только долгоживущий факт - по явному «запомни» ЛИБО когда сам его узнал (предпочтение / ограничение проекта / исправление / указатель на ресурс). Беседу, разовое и то, что уже есть в коде и истории git - НЕ пиши.
- **Куда писать:** новый файл в `./memory/` + строку-указатель в `MEMORY.md`. Встроенную авто-память Claude Code не используй: она выключена в `.claude/settings.json`, иначе память уходит в системную папку вне проекта.
- **Имена - слаги:** строчная латиница, цифры, дефис и подчёркивание, **первый символ - буква или цифра**. Не пробелы, не кириллица, не прописные - имя это идентификатор, по нему ссылаются из индекса и из `[[связей]]`. Правило то же и для подпапок. Имя файла - всегда латиницей, даже если содержимое на русском: язык проекта относится к тексту факта, а не к его имени.
- **Форма строки индекса одна:** `- [Заголовок](имя-файла.md) - крючок`. Адрес - голый путь, без угловых скобок и без подсказки в кавычках. Другие формы markdown (`- [Текст][метка]`, `- [метка]`) проверка не принимает: первую отвергает с ошибкой, вторую вообще не считает строкой индекса.
- **Под-индекс - это подпапка и то же имя:** `memory/infra/MEMORY.md`. На него обязательна строка из корневого индекса, иначе всё, что за ним, агенту невидимо. Метка `orphan: true` этого не лечит - до под-индекса всё равно неоткуда дойти.
- **Имя у памяти одно - имя её файла.** Поле `name` в шапке пиши в точности как называется файл без `.md`: `feedback_ask_dont_guess.md` -> `name: feedback_ask_dont_guess`. Ссылки `[[...]]` веди по нему же.
- **Файл вне индекса** (шаблон, заготовка, черновик) помечай `orphan: true` в шапке - это единственная метка, других написаний нет.
- **Новые факты пиши в тело файла, а не в `description`.** `description` - стабильный однострочный крючок про тему файла; меняй его только если сменилась сама тема.
- **Прежде чем создавать** новый файл - проверь, нет ли подходящего, и обнови его, а не плоди дубль.
- Память - точечные наблюдения на момент записи; если факт называет файл или флаг, перепроверь, что он ещё существует.
```

**8. Проверь границу git.** Если конфиг и `settings.json` лежат в `.claude/`, посмотри, не исключён ли `.claude/` из git (`git check-ignore .claude/CLAUDE.md`, `.gitignore`, `.git/info/exclude`). Если исключён - предупреди владельца: и импорт, и `autoMemoryEnabled` тогда локальные, на свежем клоне память не подхватится; для «clone-and-go» импорт нужно держать в отслеживаемом корневом `CLAUDE.md`.

**9. Отчитайся:** что выставил в `settings.json`, что перенёс из нативной памяти (если переносил) и куда заархивировал старую папку, какие файлы памяти создал, в какой конфиг и какой строкой вписал импорт, и как проверить - в новой сессии спросить «что ты знаешь из памяти?» (должен пересказать индекс, не открывая файлы) и «запомни: <факт>» (появится новый файл в `./memory/` + строка в индексе, а НЕ запись в системной папке).

**И объясни владельцу, как откатить всё назад:**
- вернуть нативную авто-память - поставить `"autoMemoryEnabled": true` (или убрать ключ / тумблер в `/memory`); если архивировал native-папку - переименовать `memory.bak` обратно в `memory`;
- выключить нашу - убрать из конфига строку импорта `@memory/MEMORY.md` и раздел «## Память»; папку `./memory/` можно оставить или удалить.

Язык памяти подбирай под язык проекта - это про ТЕКСТ факта. Имя файла всегда слаг латиницей, независимо от языка: по нему ссылаются, и кириллическое имя проверку не пройдёт.
