# Протокол памяти: единственный источник

Текст протокола разложен по трём местам, которые читает человек: [README](../README.md), раздел «Формат файла памяти»; [`CLAUDE.example.md`](../CLAUDE.example.md), шаг 2; [`setup-memory.md`](./setup-memory.md), шаги 5 и 7.

Прежде это были три независимые копии с пометкой «если правите один, правьте и другой». Пометку выполняет тот, кто о ней помнит, - и копии разошлись: одно и то же правило в README и в промпте стояло разными словами, а агент читает обе версии и выбирает ту, что удобнее ему, а не ту, что верна.

Источник теперь один - этот файл. Правите протокол - правьте только его и переносите кусок в копии дословно. Копию, разошедшуюся с источником, ловит проверка: класс `ProtocolHasOneSource` в [`../scripts/test_check_memory_index.py`](../scripts/test_check_memory_index.py) называет кусок и файл.

Куски размечены комментариями `<!-- кусок: имя -->` и `<!-- конец куска: имя -->`. Обрамляющий забор в копиях свой (в `CLAUDE.example.md` это `~~~`, в README и промпте - тройные обратные кавычки), поэтому в сравнение он не входит: сравнивается текст между заборами.

## Кусок «формат»

<!-- кусок: формат -->
```markdown
---
name: <имя этого файла без .md - в точности, буква в букву>
description: <одна строка про то, ЧЕМ является файл - стабильный крючок, не журнал фактов>
updated: <ГГГГ-ММ-ДД - когда факт перечитали последний раз>
metadata:
  type: user | feedback | project | reference
---

<сам факт. Связанные памяти линкуем через [[их-имена]].>
```
<!-- конец куска: формат -->

## Кусок «правила»

<!-- кусок: правила -->
```markdown
## Память

Долговременная память - файлы в `./memory/`: индекс `MEMORY.md` (подключён импортом выше, уже в контексте - отдельно читать не нужно) плюс по одному факту на файл с YAML-frontmatter `name` / `description` / `updated` / `metadata.type` (`user` | `feedback` | `project` | `reference`); необязательные `status` и `supersedes` говорят, действует ли факт и чем он заменён. Связи между фактами - через `[[имя-другого-файла]]`.

Правила:

- **Что записывать (не всё подряд):** только долгоживущий факт - по явному «запомни» ЛИБО когда сам его узнал (предпочтение / ограничение проекта / исправление / указатель на ресурс). Беседу, разовое и то, что уже есть в коде и истории git - НЕ пиши.
- **Куда писать:** новый файл в `./memory/` + строку-указатель в `MEMORY.md`. Встроенную авто-память Claude Code не используй: она выключена в `.claude/settings.json`, иначе память уходит в системную папку вне проекта.
- **Имена - слаги:** строчная латиница, цифры, дефис и подчёркивание, **первый символ - буква или цифра**. Не пробелы, не кириллица, не прописные - имя это идентификатор, по нему ссылаются из индекса и из `[[связей]]`. Отдельно закрыты имена `claude` и устройств DOS (`con`, `nul`, `aux`, `prn`, `com1`-`com9`, `lpt1`-`lpt9`): в нижнем регистре форму слага они проходят, но работать с ними нельзя - имена устройств DOS на Windows не создаются как обычные файлы, а сегмент `claude` не публикуют инструменты, которые сохраняют память. Правило то же и для подпапок. Имя файла - всегда латиницей, даже если содержимое на русском: язык проекта относится к тексту факта, а не к его имени.
- **Форма строки индекса одна:** `- [Заголовок](имя-файла.md) - крючок`. «Заголовок» и «имя-файла» тут заполнители - подставь настоящие; само имя файла по правилу выше пишется латиницей. Адрес - голый путь, без угловых скобок и без подсказки в кавычках. Другие формы markdown (`- [Текст][метка]`, `- [метка]`) проверка не принимает: первую отвергает с ошибкой, вторую вообще не считает строкой индекса.
- **Под-индекс - это подпапка и то же имя:** `memory/infra/MEMORY.md`. На него обязательна строка из корневого индекса, иначе всё, что за ним, агенту невидимо. Метка `orphan: true` этого не лечит - до под-индекса всё равно неоткуда дойти.
- **Имя у памяти одно - имя её файла.** Поле `name` в шапке пиши в точности как называется файл без `.md`: `feedback_ask_dont_guess.md` → `name: feedback_ask_dont_guess`. Ссылки `[[…]]` веди по нему же. Два написания на одну память - и промахнуться мимо обоих легче, чем попасть в одно.
- **Файл вне индекса** (шаблон, заготовка, черновик) помечай `orphan: true` в шапке - это единственная метка, других написаний нет. Не хочешь помечать - внеси файл в индекс.
- **Новые факты пиши в тело файла, а не в `description`.** `description` - стабильный однострочный крючок про тему файла; меняй его только если сменилась сама тема.
- **Дата и выключение факта.** `updated: ГГГГ-ММ-ДД` в шапке - когда факт перечитали последний раз; по ней проверка говорит «этот факт не трогали N дней», а без неё - что возраст неизвестен. Факт, который больше не действует, не удаляй: он объясняет, почему решение поменялось. `status` говорит, действует ли факт: `active` (или поля нет), `deprecated` (устарел, но ещё объясняет прошлое), `superseded` (заменён другим файлом - тогда в новом файле стоит `supersedes: <имя старого без .md>`). Замена объявляется с двух сторон: односторонняя либо оставляет старый факт в работе рядом с новым, либо выключает его молча - проверка называет обе половины.
- **Прежде чем создавать** новый файл - проверь, нет ли подходящего, и обнови его, а не плоди дубль.
- Память - точечные наблюдения на момент записи; если факт называет файл или флаг, перепроверь, что он ещё существует.
```
