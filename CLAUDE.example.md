# Пример протокола памяти для конфига агента

Это то, что «включает» файловую память в вашем проекте. Механики поверх модели нет - работают папка `memory/`, настройка `.claude/settings.json` и пара правил в конфиге агента (`CLAUDE.md` для Claude Code, `AGENTS.md` для совместимых).

Настройка - два шага: сначала отключить встроенную авто-память, потом вставить блок в `CLAUDE.md`. **Ровно эти же шаги выполняет промпт [`prompts/setup-memory.md`](./prompts/setup-memory.md)** - держите оба в синхроне, если правите.

## Шаг 1. Отключите встроенную авто-память Claude Code

В `.claude/settings.json` вашего проекта (создайте или смёржьте):

```json
{
  "autoMemoryEnabled": false
}
```

Зачем: у Claude Code есть своя авто-память, включённая по умолчанию, и просьбы «запомни X» уходят в системную папку `~/.claude/projects/<проект>/memory/` **мимо** вашего `./memory/`. С выключенной авто-памятью «запомни» проваливается в обычную инструкцию, и протокол ниже пишет память в проект. Подробнее - в разделе README «Про нативную память».

## Шаг 2. Вставьте блок в свой CLAUDE.md

Скопируйте блок ниже целиком. Первая строка - импорт индекса (кладёт его содержимое в контекст каждую сессию), остальное - правила. Claude Code читает и корневой `./CLAUDE.md`, и `./.claude/CLAUDE.md` - вставляйте в тот, что используете, и поправьте путь импорта под его расположение (см. дальше).

~~~markdown
@memory/MEMORY.md

## Память

Долговременная память - файлы в `./memory/`: индекс `MEMORY.md` (подключён импортом выше, уже в контексте - отдельно читать не нужно) плюс по одному факту на файл с YAML-frontmatter `name` / `description` / `metadata.type` (`user` | `feedback` | `project` | `reference`). Связи между фактами - через `[[имя-другого-файла]]`.

Правила:

- **Что записывать (не всё подряд):** только долгоживущий факт - по явному «запомни» ЛИБО когда сам его узнал (предпочтение / ограничение проекта / исправление / указатель на ресурс). Беседу, разовое и то, что уже есть в коде и истории git - НЕ пиши.
- **Куда писать:** новый файл в `./memory/` + строку-указатель в `MEMORY.md`. Встроенную авто-память Claude Code не используй: она выключена в `.claude/settings.json`, иначе память уходит в системную папку вне проекта.
- **Новые факты пиши в тело файла, а не в `description`.** `description` - стабильный однострочный крючок про тему файла; меняй его только если сменилась сама тема.
- **Прежде чем создавать** новый файл - проверь, нет ли подходящего, и обнови его, а не плоди дубль.
- Память - точечные наблюдения на момент записи; если факт называет файл или флаг, перепроверь, что он ещё существует.
~~~

## Про строку `@memory/MEMORY.md` (это ядро)

Это импорт Claude Code - он подтягивает **содержимое** индекса в контекст каждую сессию. Именно он делает индекс «всегда загруженным». Прозаическое «прочитай MEMORY.md» тоже попадает в контекст как текст, но выполнение чтения агент решает сам - импорт надёжнее.

**Путь импорта считается относительно файла, где стоит строка:**

- в корневом `./CLAUDE.md` → `@memory/MEMORY.md`
- в `./.claude/CLAUDE.md` → `@../memory/MEMORY.md` (`../` поднимается на уровень выше, к корневому `memory/`)

**`.claude/` и git.** Если ваш `.claude/` исключён из git (частый случай), то и строка импорта, и `settings.json` в нём не поедут в репозиторий: память работает локально, но на свежем клоне не подхватится. Для «clone-and-go» держите импорт в отслеживаемом корневом `CLAUDE.md`.

**Гарантии.** Инструкции в `CLAUDE.md` - это контекст, а не принудительная конфигурация: агент их учитывает, но не обязан исполнять буквально. Если нужна жёсткая гарантия (например, заставить дописывать память) - это уже hooks Claude Code, а не текст-инструкция.

## Заметки

- `[[links]]` - мягкие ссылки, по которым ходит агент; вне Obsidian они не кликабельны.
- `metadata.type` - соглашение для навигации, никакой тулинг его не парсит.

Полное описание подхода - в [README](./README.md).
