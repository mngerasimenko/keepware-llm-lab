# Как мы наполняем этот репозиторий

Репозиторий публичный, и главное правило здесь одно.

## Правило санитизации (обязательное)

**Сюда попадает только синтетика.** Каждый файл - обезличенный пример, а не выгрузка из рабочего окружения. Через это правило проходит любое добавление, без исключений.

Запрещено класть в репозиторий:

- реальные данные проектов, клиентов, пользователей (152-ФЗ - персональные данные не выкладываем никогда);
- любые секреты: токены, ключи, пароли, строки подключения, содержимое `.env`;
- внутреннюю стратегию, финансовые цели, данные по конкурентам, внутренние имена/клички систем;
- реальные пути, хосты, IP, домены внутренней инфраструктуры.

Если пример хочется сделать «как настоящий» - выдумайте нейтральный демо-проект (условный `demo-api`) и наполните его правдоподобно, но полностью вымышленно.

## Чек перед коммитом

1. Открыть diff целиком и глазами проверить каждую строку на предмет утечки из списка выше.
2. `grep` по типовым маркерам секретов (`token`, `secret`, `password`, `api_key`, `BEGIN PRIVATE KEY`) - должно быть пусто.
3. Спросить себя: если это увидит посторонний, узнает ли он что-то о реальных проектах или людях? Если да - переписать на синтетику.

## Как добавить память

1. Создать файл в `memory/` по формату из [`README`](./README.md#формат-файла-памяти).
2. Имя файла - слаг: строчная латиница, цифры, дефис и подчёркивание, первый символ буква или цифра (L6).
3. Поле `name` в шапке - в точности имя файла без `.md` (L5). Два имени у одной памяти - ошибка, а не удобство.
4. Добавить одну строку-указатель в `memory/MEMORY.md` в форме `- [Заголовок](имя-файла.md) - крючок`.
5. Прогнать `python scripts/check_memory_index.py memory` и чек санитизации выше.

## Как править саму проверку

Правило одно: **поменяли ветку - поправьте её мутацию** в `scripts/mutation_check.py`.

Мутационная проверка портит значимые ветки по очереди и требует, чтобы набор на каждую покраснел. Выжившая мутация - ветка, которую можно молча сломать. Два отказа тут жёсткие, а не предупреждения: якорь мутации, который больше не находится в коде, и мутант, который не компилируется. Второй появился не сразу - три мутации годами «ловились» синтаксической ошибкой: тестовый файл импортирует линтер на уровне модуля, загрузка падала, `unittest` отдавал ненулевой код, и инструмент печатал «поймана», не запустив ни одного теста.

```bash
python scripts/mutation_check.py --anchors-only   # быстро: все ли мутации применимы
python scripts/mutation_check.py                  # полный прогон, на чистом дереве
```

Инструмент правит файлы в рабочем дереве и возвращает обратно; оборванный прогон восстанавливается на следующем запуске - но только своя же мутация, чужую правку он не тронет.

## Как добавить скил

Раздел `skills/` - заготовка. Наполняем по мере того, как приём отработан на проектах и обезличен. Тот же чек санитизации. `prompts/` уже наполнен - добавляя туда, держите промпт самодостаточным: его копируют в чужой проект целиком.
